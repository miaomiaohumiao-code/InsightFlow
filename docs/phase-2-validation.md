# Phase 2：VOC 清洗、拆分与预览

## 使用流程

输入页点击 Preview Data → 查看总数、各来源数量、疑似异常和极短文本 → 查看原文、调整纳入选择或指定拆分方式 → Analyze VOC 保存确认。Back to Edit 返回原始输入。预览存入现有 IndexedDB 项目，兼容不含 preview 的旧项目。

## 当前规则

- 自动模式优先识别至少两个作者头（User/Author/用户名/作者、独立 u/name，或用户名紧接支持的时间戳），其次识别连续编号，再识别独立分隔线。
- 编号前若有正文，不按编号拆分，以免误拆功能列表。没有可靠结构时整块保留，不按标点、语言切换或每一个换行强拆。
- 用户可指定按空行分隔或每行一条。切换前明确提示：将重建全部派生记录，重置纳入和核对状态，以重新计算跨来源重复关系。
- 整理行首尾空格、连续横向空白、换行格式和多余空行。仅去除明确的独立页面标签；作者模式另外提取作者并清理支持的时间戳、回复/分享等独立操作标签。
- 独立 HTTP(S) URL 转存到 links；句子内部的 URL 保留。不会访问链接。原始 rawText 和每条 original 保留。
- 正文仅统一空白后进行精确比较，不做模糊、大小写、标点或跨语言语义去重。同来源、同作者信息（包括两者均未知）、链接相同且正文至少 20 个 UTF-16 字符的重复项默认排除，可勾选恢复。跨来源、不同作者及短文本重复仅提示。
- 不足 5 个文字/数字字符标记为极短，默认保留；表情不计长度但不会删除。清洗后无正文的记录默认排除，仍可查看原文。
- 自动模式下未拆分的多行正文标记边界不明；超过 1,500 个 UTF-16 字符标记长文本。人工核对不会隐藏风险标记，仅减少未核对数量。
- 少于 50 条提示样本偏少；疑似异常占纳入记录至少 30% 时提示边界风险。均可继续；零条有效记录时无法确认。
- 修改输入会清除旧 preview，修改预览选择会清除 confirmedAt。只有持久化成功才显示已确认并保存。

## 已知限制

- 无标记连续文本、作者和正文挤在同一行、嵌套回复、截图/OCR 错序、任意 HTML/CSV/JSON 导出不会可靠解析；当前接受粘贴纯文本，不是通用文件解析器。
- 无时间戳的普通昵称不自动删除。时间戳和 UI 标签主要覆盖中英文常见形式；其他语言正文可保留，但其元信息可能无法识别。
- 单条评论自身以连续编号开头、包含作者样式的引用或分隔线时仍可能误拆；应查看原文并返回编辑，或选择合适的手动分隔模式。
- 无结构多行文本可能实际是一条长评，也可能是多条短评；统计是当前候选数，不保证真实评论数量。
- 不同人匿名发表完全相同的长评可能被当成重复；可恢复。独立文本恰好等于页面标签时也可能被清除，可在原文核对后返回编辑。
- 大输入在浏览器主线程处理并保存派生文本；目前验证 2,000 条编号评论，未承诺无限容量。后续超大规模导入可考虑 Web Worker 与增量存储。

## 验证结果

- `npm test`：18 项通过，含原有 5 项及新增 13 项清洗、拆分、去重、异常计数、2,000 条输入及预览保存测试。
- `npm run lint`、`npm run typecheck`、`npm run build` 全部通过。
- 生产模式浏览器验收：4 个编号候选默认纳入 3 条；重复项可恢复到 4 条；极短评论保留；小样本可确认；刷新后确认恢复；返回编辑修改原文后旧确认失效；无结构多段保留整块并提示；按空行手动拆为 3 条。
- 未引入 AI、爬虫、外部平台 API 或云存储。
