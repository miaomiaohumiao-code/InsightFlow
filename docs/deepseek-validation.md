# DeepSeek 接入验证

日期：2026-09-15

## 实现

- `AI_PROVIDER=deepseek` 默认使用 `deepseek-flash`，服务端固定调用 DeepSeek 官方 HTTPS 接口；仍保留 OpenAI 适配。
- 密钥只保存在被 Git 忽略的本地环境文件中，没有写入源码、模板或前端产物。
- Chat Completions JSON 模式返回后，仍校验预定义 Schema、中文字段、来源、引文原文和 ID，不把 JSON 格式正确当作分析正确。
- DeepSeek 模型标识使用服务商前缀，隔离检查点；页面展示服务商，配置变化时创建新分析。
- 每任务最多 3 次尝试；余额不足/认证失败等不可重试错误停止后续批次。已完成数据保留。
- 记录输入、输出、缓存命中 Token；DeepSeek 金额显示以账单为准，不套用 OpenAI 价格。

- lint、TypeScript 和生产构建通过。

## 真实样例测试

使用现有 13 个来源、120 条评论。首次提取全部通过，但增量汇总在第 7 组因条目累积造成输出截断；此轮 22 次请求已计入累计用量。

已将原先仅写在 Prompt 中的条目预算落实为 Schema 的 maxItems；限制主题、洞察、比较、代表性引文及局限条数。所有评论仍参加后续证据核验，条目上限只限制报告摘要。

保留全部有效提取检查点与历史调用用量，从汇总阶段重新验证。最终状态与用量见 `.local/sample-test-report.json`；完整结果仅在成功后生成 `.local/sample-analysis-result.json`。

## 实际限制

- 模型存在重试，结构化输出与复杂聚合仍需持续评估。
- 固定数量的报告主题可能省略低频观点；增量压缩对输入顺序敏感。
- 原文匹配不等于语义解释正确，营销建议仍需人工抽查及实验。
- 完整证据核验的请求数随主题组数和评论批数相乘，通常比提取更耗时。
- 当前为本地运行；没有上传 GitHub、部署 Vercel 或建设完整 Insights UI。

官方依据：[JSON 输出](https://api-docs.deepseek.com/guides/json_mode)、[模型与定价](https://api-docs.deepseek.com/quick_start/pricing/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 样例驱动的进一步修正

- 按品牌交错汇总，不删减或重复评论，减少按品牌顺序输入导致的末尾品牌偏向；新增回归测试验证证据集合不变。
- 带完整品牌对比的草案仍可能超过 12,000 输出 Token，因此 DeepSeek 汇总预算提高为 24,000；提取与核验仍为 9,000。
- 调试期间有中断或未完整返回的请求未取得用量回执，累计用量将其标记为未计量，不能声称费用或调用数完全精确。

- 自有品牌优劣势强制限定到自有品牌来源组；范围外评论由程序置为不参与证据（not_mentioned），不依赖模型自行判断。范围内的虚假或跨评论引文仍拒绝。
- 无效 JSON 的重试会明确反馈转义、完整对象和精简输出要求，不重复发送完全相同的要求。

## 最终验收结果

- 真实样例分析成功：13 个来源、120 条评论，140 个有效任务（10 提取、10 汇总、120 证据核验）。
- 返回 4 个主要主题、4 条 Insight；整体分析、条件分析和证据字段均符合预定义结构。
- 独立复核 74 条不同代表引文，全部匹配原始文本对应位置；自有品牌证据均来自自有品牌来源；情感计数合计 120。
- 累计记录 202 次 API 尝试，包含本次接入调试、失败、重试与重新汇总，不能当作正常每次固定调用数；有 4 条未计量记录，实际次数与账单可能高于已记录值。
- 已记录输入 1,378,176 Token（其中缓存命中 281,205），输出 574,561 Token。费用以 DeepSeek 账单为准。
- 竞品优势候选混合了不同竞品品牌，未通过单品牌证据规则，最终数组为空；后续应按竞品分别生成候选，再做证据核验。
- 36 项离线测试、lint、TypeScript 与生产构建通过。

本次完成接口适配与样例验证，没有扩展完整 Insights 页面，也没有进行 GitHub 上传或公开部署。
