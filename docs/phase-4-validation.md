# Phase 4：OpenAI VOC 分析

## 已实现

服务端 Responses API + strict Structured Outputs；报告仍符合确认的 AnalysisResult v1.0.0。模型只生成抽取、草案及证据归属，最终引文、频率、情感计数、来源与 evidence-v1 等级由程序验证/计算。

API Key 仅通过服务端 OPENAI_API_KEY 环境变量读取，模块标记 server-only。未配置、无权限、配额不足、拒绝、截断或无效输出均给中文失败信息，不泄漏上游原始错误内容或密钥。`.env.example` 只含空密钥，真实环境文件和本地样例报告已忽略。

流程：确认数据 → 冻结快照 → 每批最多 12 个片段且受 UTF-8 字节预算限制 → 抽取并逐字验证引文 → 分批增量聚合 → 每次最多 3 个结论对所有片段核验支持/反例 → 按父 VOC ID 汇总 → 最终 Schema 校验 → 本地保存。

长评按段落优先且保护 UTF-16 代理对切为最多 1,800 字符的传输片段；原文偏移始终指向来源原文，不将片段重复计为评论。预算目前采用保守的字节/字符上限，尚非模型精确 tokenizer。

每次上游请求最多 3 次尝试，对网络、429（非余额不足）、5xx 和结构/引文错误进行有限重试；认证、拒绝、余额不足和输出未完成不盲目重试。API 设置 45 秒单次超时。单批失败保留成功批次，点击重试继续，未完成全量核验不会生成伪完整统计。输出截断当前需要缩小输入，不做自动动态二分重跑。

检查点记录每个已完成任务回执、待收回执任务、快照、模型/Prompt 版本和累计用量；IndexedDB 独立数据表，不修改原项目表。浏览器 Web Locks 防止同项目多标签页同时启动。关闭/离开页面会暂停浏览器队列，不是后台任务。已开始的上游请求可能仍计费；实例内 15 分钟缓存能复用部分丢失回执，但重启/多实例后不能保证供应商账单层的 exactly-once。

界面只包含 Analyze VOC、当前阶段、已完成/总任务数、暂停/续跑、已确认调用次数、输入/输出 tokens、已知费用估算及 JSON 下载/查看，未开发完整 Insights UI。总任务数在聚合后按实际结论数更新。

## 样例与测试结果

实际读取用户提供的 `样例数据.docx`：13 个来源、120 条候选，120 条纳入，分为 10 个初始抽取批次。补充识别 `075 · comment_date: ...` 形式，避免漏掉 5 条以日期标记的评论。原文不改写。日期不明不替换为采集日期；两个已知但跨品牌/产品的时间窗口不自动形成趋势结论。

当前环境没有 OPENAI_API_KEY，真实样例运行结果为 `blocked_missing_key`，actualOpenAICalls=0，success=false。没有真实 token 消耗，没有生成真实 AI 分析结果。详细机器报告在 `.local/sample-test-report.json`。

离线测试覆盖全流程、单批失败恢复、IndexedDB 往返、取消、长评偏移、不明日期、伪造引文、中文字段、人口标签、混杂比较、500 重试、认证/拒绝/截断、三次失败停止、用量累计。测试里的模型响应明确为合成响应，不代表真实模型分析质量。

最终检查：29 项离线测试通过，Lint 无警告，TypeScript 检查和生产构建通过。生产浏览器中验证了 Preview → Analyze VOC → 缺钥提示，原文和预览保留，失败后按钮恢复可操作。真实分析成功后的浏览器完整链路尚待密钥配置后验收。

## 成本

默认模型为 gpt-4.1-mini-2025-04-14。2026-09-15 查阅官方模型页：标准输入 $0.40/百万 tokens、缓存输入 $0.10/百万、输出 $1.60/百万。当前估价按已返回 usage 计算；其他模型显示价格未配置，不套用默认价格。供应商未返回 usage、网络断开或暂停时费用不完整，以账单为准。官方来源：https://developers.openai.com/api/docs/models/gpt-4.1-mini

请求数约为 E + A + ceil(T/3)×A，加上重试；E 是原文抽取批数，A 是验证后证据包批数，T 是最终需核验的结论/Insight/比较观察数。因此本样例不是只有 10 次请求；最终次数依实际模型输出而定。没有模型响应时不能预报确切总费用。若累计标准输入 100,000、输出 20,000 tokens，按上述单价约 $0.072，此为算例，不是本次实测。

## 尚需优化

- 实际密钥配置后的真实样例端到端验收与中文语义质量评测；当前只验证了离线合成响应下的程序路径。
- 增量聚合可能出现顺序偏差或遗漏低频主题；当前限制展示主题/卡片数量，但逐条抽取仍保留。可做多轮分层归并与低频重要主题召回。
- 全量“结论×评论”核验增加成本；需结合缓存、精确 token 预算和有覆盖度报告的召回方案优化，不能从代表性引文估计全局频率。
- 目前 Chinese 检查是字符比例启发式，人口标签过滤是规则加 Prompt；不能彻底保证语义无幻觉。原文连续匹配也不能证明引文足以支持断言，仍需人工核对和标注评测集。
- 时间与平台可比性采用保守的元信息一致规则；自由文本产品名/地区需更明确规范化。用户恢复的重复项照纳入选择计数，并披露重复风险。
- 公开部署默认未开启 AI。实例内限流（每客户端每分钟 30 个新任务）和 250 次运行预算不是持久化全站额度控制；未来需要部署级费用限制、持久化幂等/队列或访问控制。
- 结果 Schema 的 sentiment.evidence 字段保留，但总体情感使用确定性的五类计数摘要；不把整体情感分布包装成独立证据等级。

未实现账号、支付、爬虫、社媒 API、复杂云数据库或完整 Insights UI。
